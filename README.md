# 採光電卓（採光計算補助PWA）

住宅設計の**計画初期**に、1/100程度の平面・立面・配置図から読んだ数値を入れて、CADを使わず
「採光が成立しそうか」を確認するための検討用ツールです（ツーバイフォー用）。

> **確認申請用の計算ソフトではありません。**
> 法規値（補正係数の式・必要割合・境界距離のしきい値）は現在すべて**暫定・未照合**です。
> 条文・告示で確認してから使ってください（下の「法規値の差し替え」参照）。

## 構成

```
  core/state.js                  入力状態・自動保存・機能モジュール登録表
  data/windows.js                窓の種類（5種・標準サイズ）
  ui/section-svg.js              SVG断面図
icons/
```

## データ構造（入力）

- `bld`（建物・ツーバイフォー）：階数(1〜3)、1FL(設計GL+550)。**階ごとに**天井高さグループ（2,400mm／2,600mm）を選べる（例：1階2,400mm・2階2,600mm・3階2,400mmなど）
  - 天井高2,400mmの階：階高2,747／2,798mm。天井高2,600mmの階：階高2,947／2,998mm
  - 最上階は「階高」の代わりに軒高が決まる：軒高＝最上階FL＋（その階の天井高さグループの軒高。2,400mm→2,643mm／2,600mm→2,843mm）
- `room`：居室は1つ。床面積・用途地域区分・必要な採光割合を持つ
- `openings[]`：開口＝窓1つにつき1件（個数の入力はなし。窓を増やす場合は開口を追加する）。窓のある階・窓の種類・幅・高さ・窓上端（FLから）・境界種別・境界距離・軒の出・屋根勾配・庇(任意)を持つ。居室に属する全開口を合算して判定する
- 窓の種類（5種・メーカー/防火の区別なし、標準サイズ）：掃き出し窓(1600×2000)／腰窓(1600×1100)／タテスベリ窓(360×1100)／ヨコスベリ窓(690×300)／FIX窓(690×300)
- 種類を選ぶと幅・高さの数値欄にその標準サイズが入る。幅・高さは常時表示で、クリックせずそのまま編集できる。採光可能面積 ＝ 幅 × 高さ（補正なし）
- 窓上端の基本は FL+2000。数値欄・±ボタン、または図の窓を上下にドラッグして調整
- 旧バージョン（呼称5桁の入力方式）で保存したデータも、開く際に自動で幅・高さへ変換される

## 計算の流れ

1. 各階FL ＝ 1FL(550) ＋ 階高の積み上げ（階ごとの天井高さグループで階高が決まる）、軒高 ＝ 最上階FL ＋ 最上階の天井高さグループの軒高（すべて設計GL基準）
2. 窓中心の高さ ＝ 窓のある階のFL ＋ 窓上端 − 窓高さ/2
3. 窓の直上の各部分（軒先・庇）について d ＝ 境界距離 − 出、h ＝ 部分の先端高さ − 窓中心の高さ
4. d/h が最小の部分を採用 → `rules.coefficient()` で補正係数
5. 有効採光面積 ＝ 窓の採光可能面積 × 補正係数（居室に属する開口を合算）
6. 必要採光面積 ＝ 居室床面積 × 必要割合（`rules.requiredArea()`）
7. 判定：余裕 < 0 → NG ／ 余裕 < 設定% → OK（余裕小）／ それ以外 → OK

## 断面図のドラッグ操作

赤の境界線（↔）＝境界距離、緑の丸＝軒の出、窓＝窓上端の高さ。50mm単位で動きます。動かした値は入力欄にも反映されます。

窓は上下にドラッグすると、絶対高さで動きます。1階の窓を2階の高さまでドラッグすると、窓のある階が自動で2階に切り替わります（開口パネルの「窓のある階」・窓上端の基準もあわせて更新されます）。

建物の屋根の上の余白に「開口名／窓の種類」の文字（例：開口1／掃き出し窓）が出ます。ここをダブルクリック（ダブルタップ）すると、「窓の種類」のチップにカーソルが移動します。窓の絵そのものはドラッグ専用です。この位置は窓の高さドラッグの範囲と重ならないよう、常に屋根の上に固定しています。

隣地境界線の「隣地境界線」（境界の種類）の文字をダブルクリック（ダブルタップ）すると、「境界の種類」の欄にカーソルが移動します。

窓の高さが低いと「上端」「下端」の文字が重なるため、その場合は1行にまとめて表示します。

（いずれもネイティブのdblclickには頼らず、素早い2回タップ／クリックを独自に判定しています）

## 画面レイアウト

PCモニターやスマホの横画面（幅が一定以上）では、右側に断面図を大きく固定表示し、左側の数値入力だけをスクロールする2カラム表示になります。左側は数値入力用に幅を絞り、右側の断面図が画面の空いている分だけ広がります。スマホの縦画面では、断面図→建物→居室→開口→計算根拠の縦一列表示です。

建物パネルは最初に一度決めたら変えることが少ないため、開閉できる形にしています（居室・開口の変更では開閉状態は保たれます）。

## 法規値の差し替え

`js/rules/daylight-rules.js` の `zones` / `maxCoefficient` / `requiredRatios` を条文どおりに直し、
各項目の `verified: true` と `sources: ['建築基準法施行令第20条…']` を記入してください。
すべて `verified` になると、画面の「暫定」表示が自動で消えます。
式の形が変わる場合は `coefficient()` と `requiredArea()` を書き換えます（呼び出し側は変更不要）。

## 換気・排煙

採光と同じ画面・同じ開口（窓）を使い、下部のタブで「採光／換気／排煙」を切り替えます。

- 計算方法は採光と異なり、境界距離や軒の出は関係ありません。開口ごとに
  `有効面積 = 窓面積（幅×高さ） × 窓種類ごとの有効開口比率` を求め、居室の開口を合算します。
- 有効開口比率（ユーザー指定・確定値）：掃き出し窓・腰窓＝0.5、タテスベリ窓・ヨコスベリ窓＝1.0、FIX窓＝0
- 必要面積の割合は暫定です：換気1/20、排煙1/50（`js/rules/ventilation-rules.js` `js/rules/smoke-rules.js` を条文で確認してから確定してください）
- 排煙は「天井から800mm以内」の位置要件を考慮する：窓のうち、その階の天井高さ設定から800mm下がった範囲に重なる高さの部分だけを有効開口比率にかけて計算する（800mmという数値自体は暫定）
- 断面図（右側の図形）は採光用のものをそのまま表示します。境界線・軒のドラッグや、開口ラベル／境界線ラベルのダブルクリックも同じように使えます

## 換気・排煙の追加方法（今回実装済み。他の検討項目を追加する場合の参考）

1. `js/rules/<name>-rules.js`（法規層）と、必要なら `js/core/<name>-calc.js`（計算）を追加
2. `js/core/state.js` の `LC.modules` の該当項目を `enabled: true` に
3. `app.js` の `modeLabel()` `currentCalc()` に追記し、居室パネル・計算根拠パネルの分岐に追加

## 現在の制限（試作）

- 壁面の窓のみ（天窓は未対応）
- 検討する「直上の部分」は軒先と庇・下屋の2点（複雑な屋根形状・段状の壁面は未対応）
- 隣地は1面につき1つの境界のみ
- 窓の有効開口は「寸法 × 目安開口率」の簡易値
